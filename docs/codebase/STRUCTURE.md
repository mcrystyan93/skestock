### 2) Entry Points

- **Main runtime entry (orchestrated dev run):** `src/AppHost/Program.cs` — `DistributedApplication.CreateBuilder(args)` builds the SQL Server + Redis + Web resource graph and starts the Aspire dashboard.
- **Actual HTTP app entry:** `src/Web/Program.cs` — the ASP.NET Core `WebApplication` composition root; only fully functional when started via `AppHost` (no standalone Redis/SQL wiring otherwise — see `STACK.md` discrepancy note).
- **Test entry points:** `tests/TestAppHost/Program.cs` (slim Aspire host for functional tests, started implicitly by `FunctionalTestSetup.OneTimeSetUp` via `DistributedApplicationTestingBuilder.CreateAsync<Projects.TestAppHost>`).
- Selection mechanism: which "app" boots is purely determined by which `.csproj` is passed to `dotnet run`/`dotnet test` — there is no environment-variable or config-driven entry switch.

### 3) Module Boundaries

| Boundary | What belongs here | What must not be here |
|----------|--------------------|------------------------|
| `Domain` | Entities (`BaseEntity`/`BaseAuditableEntity` subclasses), enums, domain events, `IKeysetEntity` marker interface, `Roles` constants | Any project reference, EF Core attributes/fluent config, business orchestration logic |
| `Application` | Mediator commands/queries + handlers + FluentValidation validators, pipeline `Behaviours`, `Result`/`Error` types, filtering/keyset/caching helper libraries, `IApplicationDbContext`/`IIdentityService`/`IUser` interfaces | Concrete EF Core provider usage (only the `IApplicationDbContext` abstraction is allowed), ASP.NET Core types |
| `Infrastructure` | `ApplicationDbContext` (implements `IApplicationDbContext`), EF Core `IEntityTypeConfiguration<T>` classes, SaveChanges interceptors, ASP.NET Core Identity (`ApplicationUser`, `IdentityService`), Redis/HybridCache registration | Mediator commands/queries, endpoint/route definitions |
| `Web` | Minimal API `IEndpointGroup` classes, OpenAPI/Scalar wiring, exception-to-`ProblemDetails` mapping, `Program.cs` composition root | Direct EF Core queries (must go through Mediator → Application handlers), business/validation logic |
| `Shared` | Aspire/service resource-name string constants only (`Services.cs`) | Business logic, EF Core, HTTP handling — referenced only for constants |
| `AppHost` / `TestAppHost` | Aspire resource graph definitions (SQL Server, Redis, Web project references) | Any application logic — these are orchestration-only projects, never shipped as the running app itself |

### 4) Naming and Organization Rules

- **Feature-slice organization** inside `Application`: `Features/<FeatureName>/{Commands,Queries,Models}/<UseCase>/{<UseCase>Command|Query.cs, Handler.cs, Validator.cs}`, plus per-feature `<FeatureName>FilterConfiguration.cs`, `<FeatureName>SortConfiguration.cs`, `CacheConstants.cs`. Confirmed identical shape across all 4 implemented slices (`Categories`, `Items`, `Locations`, `SchoolClasses`), though command verb naming differs per slice (`Items` uses `Edit`+`Disable`/`Enable`; `Locations`/`SchoolClasses` use `Update`; `Categories` has `Create` only) — see `ARCHITECTURE.md` §4.
- **File naming**: PascalCase throughout (`GetAllCategoriesQuery.cs`, `CategoryFilterConfiguration.cs`) — one primary type per file, file name matches the type name.
- **Test mirroring**: `tests/Application.UnitTests/` and `tests/Application.FunctionalTests/` both mirror `src/Application/`'s folder tree feature-for-feature and use-case-for-use-case (confirmed via `find` listing — both have `Features/{Categories,Items,Locations,SchoolClasses}` with matching sub-paths).
- **Leftover/dead folder**: `src/Application/Models/` (top-level, distinct from `src/Application/Common/Models/`) exists but is **empty** — likely a stale scaffold artifact; don't add new files there without checking intent first. `[ASK USER]` — see `CONCERNS.md`.
- **No import-alias system** — this is C#/.NET, so there is no path-aliasing convention analogous to TS `tsconfig paths`; namespaces mirror folder paths 1:1 (e.g. `skestock.Application.Features.Categories.Commands.CreateCategory`).
